# 86.App 的技术路线：从原生到跨平台


这一节我们带来看看做一个App有哪些技术路线，我们会了解三种典型路线，生开发，H5套壳以及跨屏的开发要开发一个App 最传动也最标准的一种方式叫原生开发它的意思就是如果你想让App在iPhone上运行就按照苹果这一套技术体系来开发想让它在Android手机上运行就按照Android的技术体系再开发一套比如开发iPhone App 通常用苹果官方的开发工具Xcode 配合Swift等语言来写代码调试和测试最后再提交到App Store 开发Android App 通常用Google官方的Android Studio 配合Cottin等语言开发完成以后再打包柄发布到Google Play或者其他Android的应用市场原生开发最大的优势就是和手机系统结合的最直接系统提供的新功能和各种原生能力通常都能直接用上性能上限也比较高更容易做出符合iOS和Android各自使用习惯的体验但问题也很明显如果要同时支持iOS和Android 就得维护两套客户的代码相当于同

时维护两个App 因为同一个登录页同一个按钮同一个功能正因为iOS和Android各写一套太费劲人们就开始想能不能把网页直接拿来做App 于是H5套客户出现了它属于混合开发的一种背后的思路很好理解界面和主要逻辑还是用HTML CSS JavaScript这些网页逻辑来写然后外面再套一层原生App的客户把网页运行在一个叫Badview的组件里这样做出来的应用就可以安装到手机上也可以打包发布到应用商店这个方案最大的好处就是开发快风率高如果本来就会做网页又必须要再分别写一整套iOS和Android的界面而且通过插件它也可以用相册定位通知等一部分手机原生能力但它的短板也很明显那就是界面本质上还是运行在Webview里的网页对普通页面和简单工具来说问题不大但如果要做复杂动画高性能交互或者特别追求原生手感就容易受到Webview的限制体验很多时候不如真正的原生App 所以我们可以把H5套客简单理解成用网页技术做主体再套一个原生App外壳把它装进手机那有没有一种方法既不用iOS和Android各写一套

又能够做出接近原生App的体验呢这就要说到现在非常主流的那种方案跨平台开发它和前面的H5套客追求的很像都是希望一套代码尽量同时支持iOS和Android 但不同的是它不再只是把一个网页塞进App里而是用专门的跨平台框架来构建真正的移动应用所以在性能交互和调物手机能力这些方面通常都会更接近原生App 现在比较主流的跨平台框架里我们经常会看到两个名字 React Native和Flutter 它们都能实现一套代码多段运行但底层思路不太一样先说React Native 它最早有Facebook 也就是现在的Meta推出我们可以把它想象用一套React Native代码描述这里要有一段文字那里要有一个输入框 React Native再去调用iOS和Android对应的平台能力把界面真正显示出来比如它提供的View Tax Tax Input等组件背后TOKI和手机平台的原生能力连接起来而Flutter是Google推出的思路又不太一样它不主要依赖iOS和Android自带的界面组件而是

自带了一整套UI和渲染系统我们可以把它理解成不管运行在iPhone还是Android手机上 Flutter都带着自己一套画笔和颜料把界面的绘制出来所以同一套Flutter界面在不同平台上会更容易保持一致所以我们可以这样理解 React Native更像用一套代码去连接不同平台的原生能力 Flutter更像带着自己的一套绘制系统在不同平台上把界面画出来那发展到今天跨平台开发已经非常成熟也非常长期因为登录列表表单内容展示这些大量功能都可以共用一套代码不需要iOS和Android分别重写一遍当然跨平台也不是万能的如果产品特别依赖某个平台独有的能力或者对性能音视频硬件交互这些方面要求特别高有时候还是需要补充一些原生代码甚至直接选择原生开发但对于长期来说跨平台技术已经完全共用了我们下期见
